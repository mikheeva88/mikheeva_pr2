# Визуализатор графа зависимостей npm-пакетов

## Общее описание

CLI-приложение для визуализации графа зависимостей пакетов JavaScript (npm).
Готовые менеджеры пакетов и библиотеки для получения зависимостей
не используются.

Выполненные этапы:

- **Этап 1. Минимальный прототип с конфигурацией** — чтение и проверка
  настроек из CSV-файла.
- **Этап 2. Сбор данных** — получение прямых зависимостей пакета из
  npm-репозитория по URL. Используется только стандартная библиотека
  Python (`urllib`, `json`): программа скачивает описание последней версии
  пакета по адресу `<repo_url>/<package_name>/latest` и берёт из него
  поле `dependencies`.
- **Этап 3. Основные операции** — построение полного графа зависимостей
  (с учётом транзитивности) алгоритмом BFS с рекурсией, с ограничением
  глубины `max_depth` и корректной обработкой циклических зависимостей.
  Поддержан режим тестового репозитория.

## Тестовый репозиторий

При `test_mode,true` параметр `repo_url` — путь к текстовому файлу с
описанием графа. Пакеты называются большими латинскими буквами, каждая
строка — пакет и его зависимости через пробел:

```
A: B C
B: D
C: D
D:
```

Готовые примеры лежат в папке `tests/repos`:

| Файл         | Случай                                      |
|--------------|---------------------------------------------|
| `simple.txt` | транзитивные зависимости, общая зависимость D |
| `cycle.txt`  | циклическая зависимость A -> B -> C -> A    |
| `deep.txt`   | длинная цепочка для проверки `max_depth`    |

Готовые конфигурации для тестового режима лежат в папке `configs`:

```
run.bat configs\simple.csv        (транзитивность)
run.bat configs\cycle.csv         (цикл)
run.bat configs\deep_limit.csv    (max_depth = 2)
run.bat configs\deep_full.csv     (max_depth = 10)
```

## Функции и настройки

Настройки хранятся в файле `config.csv` (первая строка — `key,value`):

| Параметр       | Описание                                              | Допустимые значения          |
|----------------|-------------------------------------------------------|------------------------------|
| `package_name` | Имя анализируемого пакета                             | непустая строка              |
| `repo_url`     | URL-адрес репозитория (npm-реестра) или путь к файлу тестового репозитория | `https://registry.npmjs.org` или путь к файлу |
| `test_mode`    | Режим работы с тестовым репозиторием                  | `true` / `false`             |
| `ascii_tree`   | Режим вывода зависимостей в формате ASCII-дерева      | `true` / `false`             |
| `max_depth`    | Максимальная глубина анализа зависимостей            | целое число ≥ 1              |

Обработка ошибок: при неверном параметре программа выводит сообщение
`Ошибка конфигурации: ...` и завершается с кодом 1. Проверяются:

- отсутствие файла конфигурации или неверная первая строка;
- файл сохранён не в кодировке UTF-8;
- отсутствие любого параметра;
- пустое имя пакета;
- `repo_url` не начинается с `http://` или `https://` (обычный режим);
- файл тестового репозитория не существует (тестовый режим);
- `test_mode` и `ascii_tree` не равны `true` / `false`;
- `max_depth` не целое число или меньше 1.

Ошибки репозитория выводятся как `Ошибка репозитория: ...`:

- пакет не найден (сервер ответил 404);
- нет связи с репозиторием;
- репозиторий вернул данные не в формате JSON;
- строка файла тестового репозитория без двоеточия;
- пакет не найден в тестовом репозитории.

## Сборка и запуск

Нужен Python 3.8+. Сторонние библиотеки не требуются.

Запуск (по умолчанию читается `config.csv`):

```
run.bat                  (Windows)
./run.sh                 (Linux / macOS)
python src/main.py config.csv
```

Запуск тестов (из корня репозитория):

```
python -m unittest discover tests
```

## Примеры использования

Тестовый репозиторий (`test_mode,true`, `repo_url,tests/repos/simple.txt`,
`package_name,A`, `max_depth,3`):

```
> python src/main.py
Граф зависимостей:
  A -> B, C
  B -> D
  C -> D
  D -> -
```

Цикл (`repo_url,tests/repos/cycle.txt`) — программа не зацикливается:

```
Граф зависимостей:
  A -> B
  B -> C
  C -> A
```

Ограничение глубины (`repo_url,tests/repos/deep.txt`, `max_depth,2`):

```
Граф зависимостей:
  A -> B
  B -> C
```

Реальный репозиторий (`package_name,express`,
`repo_url,https://registry.npmjs.org`, `test_mode,false`, `max_depth,2`):

```
> python src/main.py
Граф зависимостей:
  express -> qs, depd, etag, once, ...
  qs -> side-channel
  ...
```

Ошибка в параметре (`max_depth,0`):

```
> python src/main.py
Ошибка конфигурации: max_depth должен быть не меньше 1
```
